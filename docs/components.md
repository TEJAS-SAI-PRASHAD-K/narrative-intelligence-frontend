# Shared components

Every page is assembled from these. If a bespoke risk chip appears on page four, this
document is what makes that visible as a defect.

The rule the table encodes: **a component that renders a contract concept exists once**.
Risk levels, provenance pills, definitions, "not measured", the six-field scorecard and
the async triad are each defined in one file and consumed everywhere.

---

## Contract primitives

### `<KpiStrip bundle={KpiBundle}>` · `<KpiCard metric={Metric}>`
`src/components/kpi/`

Fixed order everywhere: **Posts → Engagements → Authors → Sentiment → Emotions**. An
analyst should never have to re-find "Authors".

- The `(?)` renders `metric.definition` **verbatim**. No definition text exists in
  frontend source — the backend knows what the query actually summed.
- `nullable_fields` and `sample_size` are listed in the same tooltip: that is what turns
  "why is this smaller than I expected" into an answerable question.
- `value: null` renders `<NotMeasured>`, never `0`.
- Collapsible; collapsed state in `localStorage`.
- `onDrilldown` is set only in narrative-scoped mode. The card is a `<div>`, not a
  `<button>`: it contains the tooltip's own button, and nesting interactive elements is
  invalid and untabbable. The drilldown is a separate, labelled button inside it.

*Consumed by:* Overview.

### `<RiskScorecard scorecard={NarrativeScorecard}>`
`src/components/risk/RiskScorecard.tsx`

Six fields, always, in one order: **Priority · Bot-Like · Anomalous · Toxicity ·
Compass Risk · Negative Sentiment**. Identical label styling on every surface.

A fixed grid — three across, or two in a narrow sidebar. It was a wrapping flex row,
which gave the six fields a different width and a different wrap point on every surface,
so the same card read as a different shape depending on where it appeared.

**Every** label carries a tooltip saying what the signal measures and on what scale, not
only the ones that are missing: six labels in small caps over six numbers, half of them
percentages and half of them bands, is not self-explanatory to anyone who did not build
the scoring pass.

Any field in `missing[]` renders "not measured" — never `0`, never a zero-height bar.
`fusion_score` is printed with `/ 100` because it does not share the scale of the six
signals above it.

*Consumed by:* Narrative feed card, narrative detail sidebar, curate, kitchen sink.

### `<RiskDot level>` · `riskLevel.ts` · `<ScoreCell scale>`
`src/components/risk/`

Risk as colour **and** shape **and** text. `●` high, `◐` medium, `○` low, `–` not
measured — the glyph survives desaturation, and the label is always rendered beside it.
Analysts print these screens and read them in grayscale.

`<ScoreCell>` requires an explicit `scale` (`"unit"` for 0..1, `"hundred"` for 0..100),
so a new call site must look the field up in the contract. `riskLevelFromScore` and
`riskLevelFrom100` are separate functions and neither infers the scale from the value.

*Consumed by:* everywhere a score appears — scorecard, drivers, domains, cohorts,
authors, graph inspect, media verdict.

### `<NotMeasured reason>`
`src/components/risk/NotMeasured.tsx`

The em dash with its reason attached. A component rather than a string so the
explanation travels with it and an analyst is never left guessing whether they are
looking at a zero or an absence.

*Consumed by:* every surface that renders a nullable field.

### `<AiPill provenance={AiProvenance}>` · `<AiBlock value={GeneratedText}>`
`src/components/ai/`

Driven entirely by `provenance.generated_by` and `edited_by_user`. There is no list in
the frontend of "which fields are AI-written": the day the backend starts or stops
generating a field, the UI follows without a change here. `edited_by_user: true` swaps
`✨ Generated by AI` for `✎ Edited by analyst`.

`<AiBlock>` adds 👍/👎, share and regenerate around any `GeneratedText`, and renders
`text: null` as an explicit empty state rather than nothing.

*Consumed by:* narrative feed, narrative detail, curate, kitchen sink.

### `<ScoreExplainer explanation>`
`src/components/score/ScoreExplainer.tsx`

The product thesis. A slide-over rendering the formula, the normalisation, each
component's `value × weight → contribution` as a horizontal bar, the scoring version —
and a loud banner when `weights_renormalized` is true, spelling out the `missing[]`
signals and saying the score is not comparable to one computed over the full set.

A component with a null `contribution` gets **no bar at all**, not a zero-width one: a
zero-width bar and a "contributed nothing" bar look identical and only one is true.

No arithmetic happens here. `contribution` is served; recomputing it would create a
second source of truth that will eventually disagree with `app/scoring/fusion.py`.

*Consumed by:* narrative feed, narrative detail, author panel, author page, domain
detail (fed from `DomainOut.components[]`).

### `<CompassModule context={CompassContext}>`
`src/components/compass/`

The differentiator. Citations render **inline at their `char_start`/`char_end` spans**,
as superscript links into the context text — not as a flat bibliography, which would
list the same URLs while telling the analyst nothing about which sentence is sourced.

`verification_status: "insufficient_evidence"` renders an explicit "the system could not
source this claim" state naming the attempts and documents retrieved. Never an empty
box, never a spinner that never resolves — a blank panel reads as "still loading" and
an analyst will wait for something that is never coming.

`segmentContext` (13 tests) handles overlapping, out-of-order, inverted and unanchored
spans, and widens each span to whole words for display, because the backend's spans are
produced by a character budget and routinely end mid-word.

*Consumed by:* narrative detail, kitchen sink.

### `<FreshnessBar freshness={NarrativeFreshness}>`
`src/components/freshness/`

Age from `age_human`, status, the unclustered post count that makes "stale" concrete,
and **Update Now** → `POST /narratives/recluster` → job tray. Clustered results are
never refreshed silently: reclustering renumbers narratives and can split or merge them,
so the analyst decides when.

*Consumed by:* narrative feed, kitchen sink.

### `<OriginalPost post={PostOut}>`
`src/components/post/OriginalPost.tsx`

`ORIGINAL POST` tag, text, handle + platform, timestamp **with its timezone**,
engagement counts, score chips, expand-to-fullscreen, and optional `reasons[]` chips
explaining why the post surfaced. `Engagement.views: null` renders `—` with "this
platform does not report view counts", never `0`.

*Consumed by:* overview high-risk rail, drivers rail, narrative detail, author panel,
author page, curate, kitchen sink.

## Structural primitives

### `<FilterBar filters onChange onReset>`
`src/components/filters/`

Sticky. Owns nothing — reads the `FilterSpec` it is handed and calls back with a patch;
the URL is what changes. Date range with the **timezone rendered on the control**, free
text, the advanced builder, one removable chip per active filter, "Reset all", and a
"Copy link" that states why the link is enough.

`AdvancedFilters` uses a three-state toggle for booleans (Any / Yes / No) because
`is_anomalous=false` is a real filter, not an absence.

*Consumed by:* overview, feed, curate, drivers, cohorts, domains, network entry.

### `<EntityTable columns rows>`
`src/components/table/EntityTable.tsx`

Generic. Column picker persisted to `localStorage`; sortable headers that write to the
URL; virtualised above 200 rows; skeleton rows on load; empty and error states built in.
Clickable rows are real `role="button"` + `tabIndex` + Enter/Space, so the table is
usable without a mouse.

Overflow behaves one way everywhere: the header sticks on vertical scroll, the identity
column sticks on horizontal scroll (with the row's hover and selected states following
it), and an edge fade appears on whichever side has content off-screen. A wide table used
to end in a bare horizontal scrollbar under the page, which reads as a layout defect
rather than as "there is more here".

*Consumed by:* drivers, cohorts (page and panel), domains, comparisons, reports, alerts,
keys, jobs, graph inspect, narrative authors.

### `<CohortsPanel>` · `cohortColumns` · `COHORT_METHODOLOGY`
`src/components/cohorts/`

Slide-over openable from any cohort value anywhere, with the methodology disclaimer
rendered verbatim at the top. Cohort membership is a model output that drives who an
analyst treats as coordinated; presenting it as fact is the kind of quiet overclaim this
product exists to detect.

*Consumed by:* overview, feed, drivers, narrative detail, cohorts page.

### `<JobsSheet>` + `JobStore`
`src/jobs/`

A panel opened from the sidebar's Jobs item, which carries a live count of running jobs.
One row per job: kind, progress, elapsed, cancel. Polls `/jobs/{id}` at 1s backing off to
5s; on success invalidates only that kind's query families and toasts with a "view" link;
on failure shows the error and `request_id`.

It was a tray fixed to the bottom-right corner. Making a 202 visible was right; sitting
on top of the network legend and every table footer, with no way to move it, was not.

*Consumed by:* every 202 in the app.

### `<TruncationBanner stats={GraphStats}>`
`src/components/network/`

Loud, persistent, never a tooltip. Names the applied threshold, the true total and the
cut strategy, and offers "raise limit" / "narrow filters". A silently truncated graph
makes a coordinated cluster look isolated — the exact wrong error for this product.

*Consumed by:* network graph, kitchen sink.

### `<PageShell>`
`src/components/page/PageShell.tsx`

The frame every route renders inside, with the header order fixed at the component
rather than the call site: breadcrumb → title + meta → description → actions → sticky
filter bar → body. `title` and `description` are both required; the description is the
sentence that tells a first-time reader what the screen is for.

`titleSlot` replaces the title's rendered content while keeping its `h1` and its
typography — used only by narrative detail, whose title is editable in place.

*Consumed by:* every page under `src/pages/` except the full-screen graph and the
project picker, which own their layouts.

### `<EmptyState>` · `<ErrorState>` · `<TechnicalDetails>` · `Skeleton*`
`src/components/states/`

Three states, on every async surface, shipped in the same commit as the happy path.
Empty never shares styling with error: "no rows matched" is a result, not a failure.

`ErrorState` leads with `explainError()`'s plain-language translation of the backend's
`error.code` — what happened, what it means for this screen, what to do next. The
backend's own message and the `code` / HTTP status / `request_id` line sit inside
`<TechnicalDetails>`, one click away and still selectable, because a bug report has to
quote them. An untranslated code falls back to the backend's message rather than to a
vaguer sentence.

*Consumed by:* every page.

## Charts

`TimeseriesChart` (shared `syncId` for the linked brush), `ChartTooltip`,
`InsightsDonut`, `HierarchyBars`, `NarrativeTimelineChart`, `NarrativeCohortsChart`.
All colours come from `charts/palette.ts`, hashed from the series key so a series keeps
its colour across refetches and across both synced charts.

`src/lib/tokens.ts` resolves design tokens to `rgba()` for the WebGL graph, which
parses colours itself and cannot read the `hsl(H S% L% / A)` form the tokens use.

## Where to see them

`/kitchen-sink` renders every primitive in every state — loaded, loading, empty, error,
null-metric, missing-score-component, truncated-graph, AI-edited-by-user, insufficient
evidence, and a forced-grayscale risk row — from typed fixtures under
`src/components/__fixtures__/`, with no backend running.
